## D. Decisions I had to add (defaults applied unless you answer)

| D9 | Hook reference lag in E2 | **Revised in Phase 2.** Primary run `d_E2 = 0` (hook sees the benchmark bar; `eps_S(0)=0`, so buffered rules coincide with the retained-margin rule by construction). Buffered comparison at `d = 1` and `d = 5` (`--lag`). Reason for the change: the replay steps once per minute and the searcher re-corrects the pool to the benchmark every minute, so a hook reference lagged by one bar sees almost none of the opportunity that the last bar created (S_hat is about 0 while S is not). With d=1 even unbuffered rules collect about 0 and the calibrated buffer removes what remains. That is a real effect of staleness at this resolution but it dominates the comparison, so it is reported as a stress scenario, not the primary. |
| D10 | Depth used in E2 | E1 fits depth on a **trailing** window (strictly earlier swaps). E2 uses the depth fitted up to the end of the previous UTC day. Window length is chosen on validation months. An in-sample same-day depth is reported only as a descriptive upper bound. |
